s3-change-default-encryption-sse-s3-2023-01
  claim: Since 2023-01-05 all new object uploads to Amazon S3 are automatically encrypted at no additional cost; SSE-S3 is applied to all new buckets and to any existing bucket that did not already have default encryption configured.
  scope: every new object upload, all buckets; default; existing buckets with SSE-S3 or SSE-KMS configured kept their setting.
  link: [2023-01-05](../facts/s3.md#s3-change-default-encryption-sse-s3-2023-01)
  link: [SSE-S3](../facts/s3.md#s3-change-default-encryption-sse-s3-2023-01)
  say: January fifth, twenty twenty-three | S3 managed keys, S S E S three
  changed: 2023-01-05: was no base level of encryption: existing unencrypted buckets (no default encryption configured) did not encrypt new object uploads, and encryption of new uploads could be disabled
s3-versioning-delete-the-delete-marker-restores
  claim: In a versioning-enabled bucket, deleting the delete marker undeletes the object: a DeleteObject request that includes the marker's version ID permanently removes the marker, the most recent noncurrent version becomes the current version again, and a simple GET returns it. A DeleteObject request without a version ID, when the current version is a delete marker, does not remove the marker but adds another delete marker.
  scope: per object in a versioning-enabled bucket; the DELETE request names the version ID of the delete marker.
  link: [you must delete this delete marker](../facts/s3.md#s3-versioning-delete-the-delete-marker-restores)
  link: [include its version ID](../facts/s3.md#s3-versioning-delete-the-delete-marker-restores)
  link: [the most recent non-current version](../facts/s3.md#s3-versioning-delete-the-delete-marker-restores)
  link: [PUTs another delete marker](../facts/s3.md#s3-versioning-delete-the-delete-marker-restores)
s3-presigned-url-signature-must-match-request
  claim: A presigned URL carries its Signature Version 4 request signature inside the URL. It is created for a bucket, an object key, an HTTP method and an expiration time interval. The HTTP method, headers and query string must match exactly between URL generation and use; a modified query string can cause a signature mismatch, and the service denies a request whose signature does not match the signature it calculates.
  scope: per presigned URL request (SigV4).
  link: [the request signature is part of the URL](../facts/s3.md#s3-presigned-url-signature-must-match-request)
  link: [match exactly between URL generation and usage](../facts/s3.md#s3-presigned-url-signature-must-match-request)
  link: [the service denies the request](../facts/s3.md#s3-presigned-url-signature-must-match-request)
  link: [potentially causing signature mismatches](../facts/s3.md#s3-presigned-url-signature-must-match-request)
s3-change-bpa-acls-default-new-buckets-2023-04
  claim: Since 2023-04-27 Amazon S3 automatically enables S3 Block Public Access and disables ACLs for all new buckets in all AWS Regions.
  scope: new buckets, all Regions; default; settings can be changed after creation.
  link: [2023-04-27](../facts/s3.md#s3-change-bpa-acls-default-new-buckets-2023-04)
  link: [Block Public Access turned on by default](../facts/s3.md#s3-change-bpa-acls-default-new-buckets-2023-04)
  link: [ACLs are disabled by default](../facts/s3.md#s3-change-bpa-acls-default-new-buckets-2023-04)
  say: April twenty-seventh, twenty twenty-three | Block Public Access is on by default | ACLs are off by default
  changed: 2023-04-27: was Block Public Access on and ACLs disabled only as console defaults; buckets created with the S3 API, S3 CLI, the AWS SDKs or AWS CloudFormation did not get these settings by default
s3-sse-s3-default-every-bucket
  claim: Every S3 bucket has encryption configured by default and every new object is encrypted at rest with SSE-S3 unless another type is chosen. To use another type, name it in the PUT request (SSE-KMS, DSSE-KMS or SSE-C) or change the bucket default to SSE-KMS or DSSE-KMS.
  scope: per bucket; default; adjustable.
