## [AWS infrastructure](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/aws-infrastructure.md)

- [Availability Zones](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/availability-zones.md): AWS operates over 100 Availability Zones within several Regions around the world (current numbers can be found here: AWS Global Infrastructure).
- [Regions](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/regions.md): Each AWS Region consists of multiple independent and physically separate Availability Zones within a geographic area.
- [AWS Local Zones](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/aws-local-zones.md): AWS Local Zones are a type of infrastructure deployment that places compute, storage, database, and other select AWS services close to large population and industry centers.
- [AWS Outposts](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/aws-outposts.md): AWS Outposts is a family of fully managed solutions delivering AWS infrastructure and services to virtually any on-premises or edge location for a truly consistent hybrid experience. Outposts solutions allow you to extend and run native AWS services on-premises, and are available in a variety of form factors, from 1U and 2U Outposts servers to 42U Outposts racks, and multiple rack deployments.
- [Points of presence](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/points-of-presence.md): In addition to the AWS Regions and Availability Zones, AWS also operates a globally distributed point of presence (PoP) network.
- [Partitions](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/partitions.md): AWS groups Regions into partitions.
- [Control planes and data planes](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/control-planes-and-data-planes.md): AWS separates most services into the concepts of control plane and data plane.
- [Static stability](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/static-stability.md): One of the most important resilience characteristics of AWS services is what AWS calls static stability.
- [Summary](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/summary.md): AWS utilizes different fault containers in our infrastructure to create fault isolation.


## [AWS service types](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/aws-service-types.md)

- [Zonal services](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/zonal-services.md): Availability Zone Independence (AZI) enables AWS to offer zonal services, like Amazon EC2 and Amazon EBS.
- [Regional services](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/regional-services.md): Regional services are services that AWS has built on top of multiple Availability Zones so that customers don’t have to figure out how to make the best use of zonal services.
- [Global services](https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/global-services.md): In addition to Regional and zonal AWS services, there is a small set of AWS services whose control planes and data planes don’t exist independently in each Region.
