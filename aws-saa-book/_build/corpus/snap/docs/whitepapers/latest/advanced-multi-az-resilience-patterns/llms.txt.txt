# Advanced Multi-AZ Resilience Patterns Detecting and Mitigating Gray Failures

> Many customers run their workloads in highly available, multi-Availability Zone (AZ) configurations. These architectures perform well during binary failure events, but often encounter problems with "gray" failures. The manifestations of this type of failure can be subtle, and defy quick and definitive detection. This paper provides guidance on how to instrument workloads to detect impact from gray failures that are isolated to a single Availability Zone, and then take action to mitigate that impact in the Availability Zone.

## [Multi-AZ observability](https://docs.aws.amazon.com/whitepapers/latest/advanced-multi-az-resilience-patterns/multi-az-observability.md)

- [Failure detection with CloudWatch composite alarms](https://docs.aws.amazon.com/whitepapers/latest/advanced-multi-az-resilience-patterns/failure-detection-with-cloudwatch-composite-alarms.md): In CloudWatch metrics, each dimension set is a unique metric, and you can create a CloudWatch alarm on each one.
- [Failure detection using outlier detection](https://docs.aws.amazon.com/whitepapers/latest/advanced-multi-az-resilience-patterns/failure-detection-using-outlier-detection.md): One gap with the previous approach could arise when you see elevated error rates in multiple Availability Zones that are occurring for an uncorrelated reason.
- [Failure detection of single instance zonal resources](https://docs.aws.amazon.com/whitepapers/latest/advanced-multi-az-resilience-patterns/failure-detection-of-single-instance-zonal-resources.md): In some cases, you might have a single active instance of a zonal resource, most commonly systems that require a single-writer component such as a relational database (such as Amazon RDS) or a distributed cache (such as Amazon ElastiCache (Redis OSS)).
- [Summary](https://docs.aws.amazon.com/whitepapers/latest/advanced-multi-az-resilience-patterns/summary.md): This section described three approaches to help identify single Availability Zone impairments.


## [Availability Zone evacuation patterns](https://docs.aws.amazon.com/whitepapers/latest/advanced-multi-az-resilience-patterns/availability-zone-evacuation-patterns.md)

- [Availability Zone independence](https://docs.aws.amazon.com/whitepapers/latest/advanced-multi-az-resilience-patterns/availability-zone-independence.md): To achieve the first outcome, to stop sending work to the impacted Availability Zone, evacuation requires that you implement Availability Zone Independence (AZI), also sometimes called Availability Zone Affinity.
- [Control planes and data planes](https://docs.aws.amazon.com/whitepapers/latest/advanced-multi-az-resilience-patterns/control-planes-and-data-planes.md): Before we get to the actual patterns you can use to perform an Availability Zone evacuation, we need to discuss the concepts of control planes and data planes.
- [Data plane-controlled evacuation](https://docs.aws.amazon.com/whitepapers/latest/advanced-multi-az-resilience-patterns/data-plane-controlled-evacuation.md): There are several solutions that you can implement to perform an Availability Zone evacuation using data plane-only actions.
- [Control plane-controlled evacuation](https://docs.aws.amazon.com/whitepapers/latest/advanced-multi-az-resilience-patterns/control-plane-controlled-evacuation.md): The first pattern uses data plane operations to prevent performing work in an impacted Availability Zone to mitigate the impact of an event.
- [Summary](https://docs.aws.amazon.com/whitepapers/latest/advanced-multi-az-resilience-patterns/evacuation-summary.md): This section summarizes the pros and cons of the evacuation patterns described.
